# 蜂鸟（Hummingbird）· 部署指南

> 对应设计文档 v0.8（docs/自研消息网关设计文档.md）· 2026-11-09 编写
> ⚠️ 本指南先于软件编写，交付时逐条实测核对后转为正式版。
> 适用：树莓派 3B+（arm64 或 armv7 系统）/ 任何小内存 Linux。

## 0. 前置检查（30 秒）

```bash
uname -m        # aarch64 → 用 arm64 包；armv7l → 用 armhf 包
free -h         # 确认至少 50MB 可用内存（本应用全量 <16MB，绰绰有余）
```

交付物是**单个文件**：可执行二进制 `hummingbird`（musl 静态编译，无任何运行时依赖，Web 管理台内嵌其中，没有独立前端程序）。

## 1. 放置与启动（自配置，无自安装）

```bash
# ① 开发机上传
scp hummingbird pi@<pi-ip>:~/

# ② 放到固定目录并前台试跑（数据库默认生成在工作目录）
sudo mkdir -p /opt/hummingbird && sudo mv ~/hummingbird /opt/hummingbird/
cd /opt/hummingbird && sudo ./hummingbird
#    → stdout 打印初始 admin 密码（抄下来），浏览器验证 http://<pi-ip>:8080

# ③ 验证 OK 后 Ctrl+C，按《自研消息网关运行时默认与自启动.md》配 systemd 常驻
```

默认值速记：数据库 `./hummingbird.db`（工作目录相对）、日志 stdout/stderr、监听 `0.0.0.0:8080`；环境变量 `HB_DB_PATH` / `HB_PORT` 可覆盖。完整说明与 unit 模板见《运行时默认与自启动》文档。

## 2. 首次登录

浏览器打开 `http://<pi-ip>:8080`（建议直接用 Tailscale 的 `100.x.x.x` 地址，只在你的设备网内可达）。

- 账号 `admin` + 首次启动 stdout 打印的初始密码（试跑终端或 `journalctl -u hummingbird | head` 可见），**首次登录强制改密**
- 进去后的准备顺序：**§3 配渠道 → 模板页建模板（{{host}} 等占位符）→ 任务页建任务**。任务 = 绑定多个"模板 → 渠道组"，生成该任务唯一的 token（明文只显示一次，存好）；脚本一律用任务 token 调推送接口

## 3. 配置渠道

Web 台 → 渠道 → 添加。各渠道需要预先准备的东西：

| 渠道 | 你要准备的 | 获取方式 |
|---|---|---|
| 钉钉机器人 | webhook 地址 +（可选）加签 secret | 群设置 → 机器人 → 自定义 |
| 企微机器人 | webhook key | 群右键 → 添加机器人 |
| 企微应用 | corpid + agentid + secret | 自建免费企业 → 应用管理；**关注企微的微信插件后消息直达个人微信** |
| 飞书机器人 | webhook +（可选）签名 key | 群设置 → 机器人 |
| Telegram | bot token | @BotFather → /newbot |
| Bark | 设备 key | iOS App 里复制 |
| ntfy | 主题名 | 任意字符串，手机订阅即可 |
| 通用 webhook | URL | 接任意自建服务 |

**每配一个渠道，立刻点"测试消息"按钮验证**——这也是代理配置的验证器。

### Telegram 专属：走代理

Telegram 在国内必须经代理。编辑该渠道，`proxy` 字段填本机 mihomo：

```
http://127.0.0.1:7890        （mihomo mixed/http 端口）
socks5://127.0.0.1:7891      （mihomo socks 端口）
```

注意两层职责：**蜂鸟只负责把请求送进 mihomo，能不能出去取决于 mihoma 的分流规则**（TG 流量需匹配到境外节点）。国内渠道（钉钉/企微/飞书）`proxy` 留空直连。排障看 Web 台推送日志的 `via_proxy` 和 `error` 列。

## 4. 发消息：调用任务 token（渠道由任务的绑定决定）

```bash
# ① 单发（POST，最常用）
curl -s -H "Authorization: Bearer <任务token>" http://127.0.0.1:8080/api/push \
  -d '{"template":"巡检","variables":{"host":"pi","status":"ok"}}'

# ② 批量：一次调用多条，各自模板与变量（同/异模板均可，各走各的绑定渠道）
curl -s -H "Authorization: Bearer <任务token>" http://127.0.0.1:8080/api/push \
  -d '{"messages":[{"template":"巡检","variables":{"host":"pi"}},{"template":"备份","variables":{"size":"2G"}}]}'

# ③ 一行流（GET，脚本里最省事；template 之外的任意查询参数即变量）
curl -s "http://127.0.0.1:8080/push/<任务token>?template=巡检&host=pi&status=ok"
```

## 5. 定时消息：交给系统 cron

蜂鸟不内置定时（设计决策），一行 crontab 搞定：

```bash
crontab -e
# 每天 8:30 发晨报
30 8 * * * curl -s -H "Authorization: Bearer <任务token>" http://127.0.0.1:8080/api/push -d '{"template":"晨报","variables":{"date":"auto"}}'
```

## 6. 日常运维

| 操作 | 命令 |
|---|---|
| 看运行状态 | `systemctl status hummingbird` |
| 看进程日志 | `journalctl -u hummingbird -f` |
| **验证内存指标** | `ps -o rss= -C hummingbird`（应 < 8MB 空闲） |
| 升级 | 见下方「一条命令升级」 |
| 备份 | `sudo systemctl stop hummingbird && sudo cp /opt/hummingbird/hummingbird.db ~/backup/ && sudo systemctl start hummingbird` |
| 恢复 | 反向拷回 .db 后重启服务 |
| **admin 密码丢失** | `sudo /opt/hummingbird/hummingbird reset-password`（打印新随机密码） |
| 卸载 | `sudo systemctl disable --now hummingbird && sudo rm /etc/systemd/system/hummingbird.service && sudo systemctl daemon-reload`；删数据 = 删 `/opt/hummingbird` |

### 一条命令升级（推荐）

```bash
curl -fsSL https://raw.githubusercontent.com/canyuda/hummingbird/main/scripts/upgrade.sh | sudo bash
# 指定版本：sudo bash upgrade.sh v0.1.2
# 国内加速：curl -fsSL .../upgrade.sh | sudo env HB_GH_PROXY=https://ghproxy.net/ bash
```

脚本自动完成：识别架构（arm64/armv7/amd64）→ 下载对应 Release 产物 → sha256 校验 → 旧版备份为 `hummingbird.bak` → 替换并重启 systemd 服务（数据不动）。安装目录默认 `/opt/hummingbird`，可用 `HB_INSTALL_DIR` 覆盖。手动方式：上传新文件覆盖 → `sudo systemctl restart hummingbird`。

环境变量（一般不用动）：`HB_DB_PATH`（默认 `./hummingbird.db`，相对工作目录）、`HB_PORT`（默认 8080）。

## 7. 故障排查

| 症状 | 查什么 |
|---|---|
| 起不来 | `journalctl -u hummingbird -n 50`；端口占用 `ss -ltnp \| grep 8080` |
| TG 全失败、其他渠道正常 | mihomo 是否在跑；分流规则是否覆盖 TG；换 http/socks5 协议试试 |
| 全渠道失败 | 服务本身；看推送日志 error 列 |
| Web 台打不开 | 用 `http://127.0.0.1:8080` 在 Pi 本机 curl 排除网络层；确认走的是 LAN IP 还是 100.x |
| 登录暴力锁定 | 等 15 分钟，或 `sudo systemctl restart hummingbird`（锁在内存态，重启即清） |
